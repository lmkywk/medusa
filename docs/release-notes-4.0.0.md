本版改动
=========

4.0.0 是「基础包 + AI 只读摘要」版本。执行的默认行为没有变化：自适应风险预算仍是影子模式，
只记录「本应拦截」，不改变任何执行；AI 只出聚合摘要，不参与执行、不改计划、不改队列。

一、请求级指标（M3）
- 新增 RpcMetrics：每个域 / 每个 RPC 方法的请求数、耗时、1009/1004、失败原因、被拦截数。
- 埋点在 ApplicationHook 的统一收口，全部请求都过；只记方法名与状态，不记标题、不记 URL、不记参数。
- 按天聚合，保留 7 天；内存累加 + 节流落盘，单次请求不做 IO。
- 状态页/AI 摘要可直接读取：`metrics/rpc_metrics.json`。

二、风险预算框架（M3，默认影子）
- 新增 RiskBudget：每日硬上限 + 令牌桶 + 最小间隔 + 试探单发 + 手动 override。
- 默认 `mode=shadow`：只计算并记录「本应拦截」，**不拦截任何请求**，所以本版执行行为不变。
- 查询/列表类接口永不拦（状态探针被挡住会让面板失联）。
- 影子统计落在 `metrics/budget_shadow.json`，并给出「每日上限偏紧 / 令牌桶偏紧 / 最小间隔偏紧」的建议。
- 切 enforce 需在 `risk_budget.json` 里显式改 `mode`，并等数据期结论后再定参数。

三、发布自动化（M3）
- `tools/release.sh <版本>`：工程状态 → 单元测试 → 构建 → npatch 生成宿主 → 签名校验 → 版本校验
  → 组装交付目录 → SHA256 → 生成说明。任一步失败即停。
- 校验项固定为 Medusa 正式证书 SHA-256 与 versionName，避免签错包/版本错。

四、数据迁移框架（M3）
- schemaVersion + 迁移注册表 + 迁移前备份 + dry-run + 自定义计划保护。
- 配置 / 计划 / 账本 schemaVersion 1 → 2；迁移只做「补字段、规范化取值」，不新增业务数据。
- 计划迁移**绝不新增或替换用户计划**（自定义编排受保护）；账本只迁移最近 7 天目录。
- 迁移前原文件复制到 `bak/migration-<时间戳>/`；`DataMigration.dryRunForCurrentAccount()` 可先看报告。

五、god class 试点：海洋 / 摸鱼（M3）
- 新增 OceanFacade（计划目标分发）与 OceanFishTasks（摸鱼编排），把编排从 AntOcean 里搬出来。
- 旧编排原样保留为 `antfishRunLegacy`，用 `AppConfig.oceanFishSplit` 一键回退（默认走新路径）。
- 不是全量重写：有状态的动作实现仍在 AntOcean，只是通过 Port 接口暴露，失败面最小。

六、测试（M4）
- golden test 54 项，纯 JVM、不依赖设备：TaskCapability 分类、手动队列状态合并、RiskGuard 冷却、
  计划时间计算、RPC 归类、AI 脱敏与校验。
- 回放 harness：语料格式（JSONL）+ 脱敏 + 可注入时钟/随机 + starter 语料（已知信封形状）。
  真实抓包语料在数据期补入，补入前必须过 `tools/replay/desensitize.sh`。
- 本地 CI：`tools/ci.sh [test|build|verify|licenses|all]`。

八、AI 只读层（本版新增）
- 新增内置 OpenAI 兼容客户端：根地址 / 模型名 / Bearer 令牌三项不齐就不调用；
  stream=false、读超时 180 秒、失败重试 2 次、每天最多 120 次、两次调用最小间隔 20 秒。
- 每日/异常摘要：把当天聚合数字交给模型归因，产出结论/失败域/原因/建议，落盘 `ai/daily-<日期>.json|.md`，
  可查看、可导出、可按需通知。数字全部由本地代码算，模型只做归因。
- 手动任务说明：没有深链的手动任务，生成一句「去支付宝哪里做什么」，按 域+标题 缓存，每天最多 10 条。
- 未知任务样本采集：分类不出来的任务在本地留样本（脱敏），作为 4.1 分类规则的输入。
- 期末汇总：数据期结束后一次性生成，输出未知任务清单、真实耗时分布、失败原因排行、预算建议。
- 两条边界固定不可调：只发聚合数字（不发达日志/令牌/好友/URL）；模型回复必须过 JSON 校验，
  含执行意图一律丢弃，AI 不执行、不改计划、不改队列、不参与风险预算。
- 入口：设置页 →「执行与风控」→「AI 分析（只读）」。
- 配置页交互：改完点「保存配置」（有未保存提示与保存时间）；「测试连接」会先保存再发一条
  16 tokens 的最小请求，直接显示成功/失败原因与耗时，不用等到第二天看摘要。
- 用量估算：本地记录调用次数与字符数（不记内容），按「汉字 1 token、其他字符 4 字符 1 token」
  估算，按中文习惯用「万 / 亿」显示；给出「每天 1 次摘要 + 10 条说明 ≈ 每月多少万 tokens」的量级预估。
- max tokens 的含义在页面上写明：它是**单次回复**上限，不是总额度；摘要通常 200–500 tokens，
  1024 够用，调大只在回复被截断时需要，按实际用量计费不会因此更贵。
- 推理模型兼容：`deepseek-flash` 这类模型会把思考过程也计入 max tokens，实测 1024 可能被思考占满
  而正文为空。现在检测到 `finish_reason=length` 且正文为空时，会自动用两倍上限重试一次（最多 8192），
  并把原因写进摘要失败记录，不再笼统报“调用失败”。
- 用量优先取服务端返回的真实 token 数（`usage.total_tokens`），拿不到才用本地估算；
  实测一次完整摘要约 1306 tokens。

九、首页 hero 背景
- 默认背景换成新的「翡翠森林·蛇灵守护者」图（`home_default.jpg`，用户提供），渐变只作为解码前底色。

- 背景选择器里的「默认」缩略图同步换成新图。

十、顺带修正
- TaskCapability：交易/履约类名词（订单/评价/点赞/转化/闯关/招募/充值/支付）带 timeCount 时
  不再被判为 WAIT，一律 REAL_ACTION，避免这类任务被伪申报。
- RpcMetrics 归类：非 JSON 的 1009/1004 信封也会被识别（否则每域 1009 率会算低）；
  字符串结果码按语义判断（`SUCCESS/OK` 成功、`FAIL/ERROR` 失败），未知字符串码不算失败，
  顶层 `success=false` 才算失败——避免把 `resultCode:"SUCCESS"` 这类正常响应计成故障。
- RiskGuard 的 1009 冷却升级计算抽成纯函数 RiskCooldown，行为不变、可单测。

待验证（进数据期）
- 4.0.0 装完后按正常节奏使用，不改 UI、不调计划、不装小包；只看指标、影子预算与每日摘要。
- 只有 P0（崩溃 / 1009 连续 / 任务丢失）才打断；其他问题进 backlog，4.1 一起做。
- 数据期结束后据此确定风险预算参数、补全回放语料、继续 god class 拆分。
